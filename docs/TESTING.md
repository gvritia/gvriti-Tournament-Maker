# Тестирование

Тестирование Tournament Maker включает автоматические backend-тесты, проверку качества кода, проверку миграций и ручную проверку пользовательских сценариев через API и frontend.

## Автоматические тесты

Тесты находятся в папке `backend/tests`.

```powershell
cd backend
pytest
```

Основные группы тестов:

- `test_auth.py` - регистрация, вход, JWT и стартовые данные пользователя;
- `test_crud.py` - базовые CRUD-операции;
- `test_owner_scope.py` - изоляция данных пользователей;
- `test_schedule.py` - генерация расписания и календарные ограничения;
- `test_cups.py` - кубковый турнир;
- `test_matches.py` - матчи, судьи и цены билетов;
- `test_lineups.py` - составы команд;
- `test_match_protocol.py` - события и завершение матча;
- `test_random_results.py` - случайные результаты;
- `test_standings.py` - турнирная таблица;
- `test_statistics.py` - статистика игроков.

## Проверка качества кода

```powershell
cd backend
ruff check .
black --check .
```

`ruff` используется для статического анализа, а `black` - для проверки форматирования.

## Проверка миграций

```powershell
cd backend
alembic check
```

Команда помогает убедиться, что модели SQLAlchemy и миграции Alembic не расходятся.

## Ручное тестирование

После запуска backend можно открыть Swagger UI:

```text
http://127.0.0.1:8000/docs
```

Ручная проверка включает:

- регистрацию и вход пользователя;
- получение JWT-токена;
- создание сезона, команд, игроков и стадионов;
- создание чемпионата или кубка;
- генерацию расписания;
- заполнение протокола матча;
- генерацию случайного результата;
- просмотр турнирной таблицы и статистики.

Отдельно проверяется, что один пользователь не может получить доступ к данным другого пользователя.
