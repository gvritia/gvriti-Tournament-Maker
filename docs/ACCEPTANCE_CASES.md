# Приемочные сценарии

Документ содержит основные сценарии, по которым можно проверить работоспособность Tournament Maker.

## Авторизация

- пользователь может зарегистрироваться с nickname, email и паролем;
- пользователь может войти в систему и получить JWT-токен;
- защищенные маршруты недоступны без JWT;
- неверные учетные данные возвращают ошибку;
- после регистрации новый пользователь получает стартовые данные.

## Изоляция данных

- пользователь видит только свои сезоны, команды, игроков, матчи и статистику;
- пользователь не может создать матч с чужой командой или чужим стадионом;
- прямой запрос к чужой сущности не раскрывает данные;
- после входа другим пользователем старые данные не должны отображаться.

## Справочники

- доступны операции создания, просмотра, изменения и удаления сезонов;
- доступны операции с командами;
- игроки связаны с командами через `team_id`;
- стадионы могут быть связаны с домашней командой;
- доступны операции с судьями;
- доступны операции с турнирами.

## Матчи

- матч создается только с сезоном, турниром, двумя разными командами, стадионом и датой;
- при создании матча рассчитывается цена билета;
- судья может быть назначен только если он свободен в указанное время;
- завершенный матч нельзя редактировать обычным способом;
- удаление завершенного матча запрещено.

## Расписание

- команда не может играть более одного матча в день;
- команда не может играть более двух матчей в неделю;
- чемпионат и кубок вместе учитываются при проверке нагрузки;
- генерация чемпионата создает домашний и гостевой матч для каждой пары команд;
- при невозможности сформировать корректное расписание операция не должна оставлять частично созданные данные.

## Кубок

- полуфиналы создаются для четырех уникальных команд;
- финал создается только после завершения двух полуфиналов;
- ничья в полуфинале блокирует создание финала;
- сетка кубка показывает полуфиналы, финал, победителей и чемпиона.

## Составы

- в состав матча можно добавить только игрока одной из команд-участниц;
- один игрок не может быть добавлен в состав одного матча дважды;
- в составе одной команды не должно быть одинаковых игровых номеров;
- автоматическая генерация состава должна учитывать доступных игроков.

## Протокол матча

- событие матча можно добавить только для команды-участницы;
- игрок события должен принадлежать команде-участнице;
- итоговый счет должен соответствовать количеству голевых событий;
- после завершения матча обновляются статистика игроков и турнирная таблица.

## Турнирная таблица и статистика

- турнирная таблица считается только по завершенным матчам чемпионата;
- кубковые матчи не влияют на таблицу чемпионата;
- статистика игроков считается по событиям завершенных матчей;
- лидерборды доступны по голам, передачам, сейвам, желтым и красным карточкам.

## Frontend

- пользователь может войти и выйти из системы;
- основные разделы доступны из навигации;
- формы позволяют создавать и редактировать основные сущности;
- ошибки backend отображаются пользователю;
- опасные действия требуют подтверждения;
- интерфейс не должен показывать данные другого пользователя.
