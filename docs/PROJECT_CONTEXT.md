# Контекст проекта Tournament Maker

## Назначение

Tournament Maker - учебная система для организаторов футбольных соревнований. Приложение предназначено для ведения национального чемпионата и кубкового турнира в рамках сезонов. Система хранит данные о пользователях, командах, игроках, стадионах, судьях, турнирах, матчах, составах, протоколах, билетах, турнирной таблице и статистике игроков.

Каждый организатор работает только со своими данными. Для этого предметные сущности связаны с пользователем через поле `owner_id`.

## Основные сущности

- `User` - учетная запись организатора.
- `Season` - сезон соревнований.
- `Team` - футбольная команда.
- `Player` - игрок команды.
- `Stadium` - стадион.
- `Referee` - судья.
- `Tournament` - чемпионат или кубок внутри сезона.
- `Match` - матч с командами, стадионом, датой, счетом и ценой билета.
- `MatchLineup` - состав команды на матч.
- `MatchEvent` - событие протокола матча.
- `TeamSeasonStats` - турнирная таблица чемпионата.
- `PlayerSeasonStats` - сезонная статистика игроков.

## Основные возможности

- регистрация и вход пользователя;
- JWT-авторизация;
- CRUD для сезонов, команд, игроков, стадионов, судей и турниров;
- создание и редактирование матчей;
- генерация расписания чемпионата;
- генерация кубковой сетки;
- назначение судей;
- расчет цены билетов;
- работа с составами команд;
- ведение протокола матча;
- генерация случайных результатов;
- пересчет турнирной таблицы;
- пересчет статистики игроков;
- наполнение demo-данными.

## Бизнес-правила

- данные разных пользователей изолированы;
- пользователь не может ссылаться на чужие команды, сезоны, стадионы, турниры, матчи, составы и события;
- названия сезонов и команд уникальны в рамках одного пользователя;
- матч содержит `home_team_id` и `away_team_id`;
- игрок хранится как отдельная сущность и связан с командой через `team_id`;
- цена билета хранится в матче;
- стадионы не зависят напрямую от сезонов;
- судья хранится в матче через `referee_id`;
- составы хранятся в `MatchLineup`;
- события протокола хранятся в `MatchEvent`;
- команда не может играть более одного матча в день;
- команда не может играть более двух матчей в неделю;
- чемпионат и кубок вместе учитываются в календарных ограничениях;
- судья не может быть назначен на параллельные матчи;
- завершенный матч нельзя изменять обычными операциями редактирования;
- турнирная таблица пересчитывается по завершенным матчам чемпионата;
- кубковые матчи не влияют на турнирную таблицу чемпионата;
- статистика игроков пересчитывается по событиям завершенных матчей.

## Чемпионат

Чемпионат формируется по круговой системе. Каждая команда играет с каждой другой командой два раза: один матч дома и один матч в гостях. При генерации расписания учитываются календарные ограничения команд и доступность стадионов.

## Кубок

Кубковый турнир состоит из полуфиналов и финала. Полуфиналы могут быть сформированы из выбранных четырех команд или из команд с лучшими местами прошлого сезона. Финал создается после завершения двух полуфиналов и определения победителей.

## Demo-данные

В проекте есть скрипт `backend/app/scripts/seed_demo_data.py`. Он создает demo-пользователя, сезон, чемпионат, кубок, команды, игроков, стадионы, судей и матчи. Demo-данные используются для быстрой проверки и демонстрации работы системы.

## Ограничения MVP

В текущей версии не реализованы:

- онлайн-оплата билетов;
- мобильное приложение;
- интеграция с внешними спортивными API;
- новости и публикации;
- сложная ролевая модель пользователей.
